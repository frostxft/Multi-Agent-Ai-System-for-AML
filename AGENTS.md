# Project Engineering Rules

- This repository contains the Team Zen AML capstone prototype.
- Keep implementations modular and maintainable.
- Never fabricate benchmark results or production data.
- Clearly distinguish real data, model output, synthetic test data, assumptions, and generated text.
- Preserve evidence traceability through the AML pipeline.
- Update PROJECT_STATUS.md after meaningful milestones.
- Run relevant local tests after implementation changes.
- Do not claim functionality is complete unless it has actually been implemented and verified.
- Prefer simple, justified dependencies over unnecessary infrastructure.
- Treat AML_Project_Master_Specification.md as the reference for the original project scope and requirements.
- Do not silently weaken or remove a major project requirement; document justified deviations.
